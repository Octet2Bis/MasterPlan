Fondamentaux

GTM

Configure et déclenche des balises de mesure.

Le trio GTM

Toute recette combine une balise, un déclencheur et des variables

B

Balise

Ce qui est envoyé.

Ex. événement GA4 generate_lead

D

Déclencheur

Le moment où cela part.

Ex. page de confirmation visible

V

Variable

La valeur qui précise le contexte.

Ex. form_name = demo

Organisation

Un site possède un conteneur, pas un conteneur par page

  1. Compte : l’organisation propriétaire.
  2. Conteneur Web : le site ou domaine mesuré.
  3. Espace de travail : les changements en préparation.
  4. Version publiée : l’état réellement en production.
Gouvernance : l’entreprise partenaire reste propriétaire et invite l’équipe avec les droits nécessaires.

Acquisition

Les UTM transportent l’identité de la campagne jusqu’à GA4

https://votre-landing.fr/ ?utm_source=lemlist &utm_medium=email &utm_campaign=challenge2_prospection &utm_content=email1_cta

Sans convention commune, une même campagne se fragmente en plusieurs lignes et devient difficile à comparer.

Contrôle qualité

Testez le lien comme un prospect avant l’envoi

  1. Cliquez le lien depuis un email de test.
  2. Vérifiez que la landing s’ouvre, sans erreur ni redirection cassée.
  3. Contrôlez que les UTM restent visibles après la redirection Lemlist.
  4. Ouvrez GA4 Temps réel / DebugView et retrouvez la source attendue.
  5. Notez la convention dans un fichier partagé par toute l’équipe.
Piège : une URL correcte en apparence peut perdre ses paramètres lors d’une redirection.

Dorik

Utilisez l’intégration native avant d’injecter du code

Chemin Dorik
  1. Copier l’ID GTM-XXXXXXX.
  2. Site Settings → Integrations.
  3. Coller l’ID Google Tag Manager.
  4. Publier le site.
À vérifier
  • Domaine personnalisé connecté.
  • Bon site et bon conteneur.
  • Une seule installation de GTM.
  • Site republié après modification.

Sur un autre CMS : cherchez l’intégration GTM officielle ou les champs prévus pour les deux extraits du conteneur.

Première balise

GA4 commence par un Google tag sur toutes les pages

  1. Dans GA4, récupérer l’ID du flux Web G-XXXXXXXXXX.
  2. Dans GTM, créer une balise Google tag.
  3. Renseigner l’ID, idéalement via une variable constante.
  4. Déclencheur : Initialization — All Pages pour charger le Google tag avant les autres balises.
  5. Nommer clairement : GA4 — Google tag — All Pages.
Règle : ne pas installer GA4 une deuxième fois directement dans Dorik si GTM le déploie déjà.

Modèle GA4

Dans GA4, toute interaction utile devient un événement contextualisé

generate_lead { form_name: "contact_demo", lead_type: "demande_demo", page_location: "…" }

Le nom dit ce qui s’est passé. Les paramètres précisent où, comment et dans quel contexte.

Fiabilité

Le meilleur signal est le plus proche du succès réel

1 · Clic sur “Envoyer”Faible : erreurs et abandons comptés.
2 · Form submit détectéMoyen : le CMS peut intercepter l’envoi.
3 · Message de succès visibleBon : preuve côté interface.
4 · Page de confirmationTrès bon : URL unique et testable.
5 · Événement dataLayer après succèsExcellent : preuve structurée et stable.

dataLayer

Quand l’interface est fragile, le site peut annoncer explicitement le succès

Le dataLayer est une zone structurée que le site alimente et que GTM peut écouter.

window.dataLayer = window.dataLayer || []; dataLayer.push({ event: 'lead_generated', form_name: 'contact_demo', lead_type: 'demande_demo' });

À demander au développeur ou à intégrer via les capacités du CMS. Ne jamais pousser de données personnelles en clair vers les outils analytics.

Dépannage

Lisez la chaîne dans l’ordre pour localiser la panne

  1. Le conteneur charge-t-il ? Bon ID GTM, site publié, pas de blocage.
  2. Le déclencheur voit-il l’action ? Bon événement, bon sélecteur, bonnes conditions.
  3. La balise part-elle ? Consentement, exceptions, configuration.
  4. GA4 reçoit-il ? Bon ID G-, DebugView, paramètres valides.
  5. Le rapport classe-t-il bien ? UTM, délai, portée de dimension.
Doublon fréquent : GA4 ou Hotjar installé à la fois dans le CMS et dans GTM.

Consent Mode

Basique et avancé n’envoient pas les mêmes signaux avant accord

Mode basique

Les balises Google sont bloquées avant interaction.

Aucune donnée n’est envoyée à Google tant que le visiteur n’a pas consenti.

Mode avancé

Les balises Google chargent avec un état refusé.

Elles peuvent envoyer des mesures sans cookies pour la modélisation, puis s’adaptent au choix.

Pour le Challenge 2 : appliquez le mode défini par l’entreprise partenaire ou sa CMP ; n’improvisez pas ce choix.

Ordre d’exécution

L’état par défaut doit exister avant les balises de mesure

  1. Consent Initialization : la CMP définit les états par défaut.
  2. Initialization / Page View : les balises appliquent ces états.
  3. Choix du visiteur : la CMP met à jour le consentement sur la même page.
  4. GTM : les balises avec contrôles intégrés ou exigences additionnelles réagissent.
  5. Recette : tester “tout refuser”, “tout accepter” et changement de choix.

Option comportementale

Hotjar répond à “comment”, pas à “combien”

Heatmaps et enregistrements aident à comprendre les frictions observées dans le funnel.

  1. Créer le site Hotjar et récupérer le Site ID.
  2. Ajouter la balise Hotjar Tracking Code dans GTM.
  3. Déclencher sur Page View / All Pages, avec la règle de consentement requise.
  4. Preview, publier, puis vérifier dans Hotjar.
  5. S’assurer qu’un seul code Hotjar charge par page.

Ne collectez pas “au cas où”. Définissez d’abord la question : où les visiteurs hésitent-ils, abandonnent-ils ou cliquent-ils ?

KPI d’acquisition

Trois calculs suffisent pour commencer à décider

Taux CTA = clics CTA ÷ sessions landing × 100
Taux lead = leads ÷ sessions landing × 100
Coût par lead = dépenses campagne ÷ leads

Ajoutez ensuite le taux de qualification : leads qualifiés ÷ leads. C’est lui qui rapproche le marketing du résultat business.
